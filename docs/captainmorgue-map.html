Hackathon PRD notes, 2026-11-09

CaptainMorgue

Where incidents go to die. One agent per responder, a team tree with one manager per team, and CaptainMorgue at the root holding the connections and the full record. Below: the shape so far, the rules agreed, and five ways to show it on screen.

The shape

Topology

Agents talk over A2A, and every dispatch is an event CaptainMorgue handles. Each manager keeps the ordered log for its own subtree, and gossip carries it upward. Anyone can broadcast to CaptainMorgue, which picks who should hear it and relays. CaptainMorgue holds the connections to the cluster, telemetry and log store, and people reach them through their own agent.

Agreed so far

Rules

Teams and managers

  • One agent per person, tied to their identity.
  • Teams nest. A team holds people and sub-teams.
  • One manager per team, usually the first to join.
  • The incident manager is an ordinary manager.
  • Manager down: team members and CaptainMorgue elect a new one, Raft-style.
  • A team of one folds into the team above.

Messages and the log

  • Status and the ordered log go up. Work is dispatched down.
  • Every dispatch is an event that CaptainMorgue handles.
  • Broadcasts go to CaptainMorgue, which picks who hears them.
  • Status and the running log are open to everyone involved.
  • The record holds timestamps, how each part was resolved, and improvements.

Data and tools

  • Applications run on Kubernetes. Everything else is reached from there.
  • CaptainMorgue holds the connections. People use them through their agent.
  • Read through MCP first. Generated code against an API is the fallback, run in a sandbox and logged.
  • Deep telemetry questions go to Dash0 Agent0.
  • Text only at launch. Images, audio and video later.
  • Fault injection tests CaptainMorgue: it breaks the demo cluster to start a real incident.
On screen

Five UI patterns

Each pattern answers one question a responder or manager asks during or after the incident. They share one example incident: checkout returning 502s in eu-west.

1. Command tree

Who is on this, and who is stuck?

The team tree as a live roster. Managers carry a badge, and each row shows that person's current state and last update. A row that has gone quiet stands out without anyone asking. When a manager drops, the election result shows on the team row. This is the manager's home view.

2. Swimlane timeline

What happened, in what order, and did anyone collide?

One lane per person on a shared clock. Dots are actions, blue diamonds are decisions, and a red ring marks an action that conflicts with someone else's decision. Green marks a part resolved. This is the replayable log, live during the incident and the backbone of the record after.

3. Relay feed

Who did CaptainMorgue tell, and why them?

Every broadcast shows its route through the root and the reason CaptainMorgue picked each recipient. Showing the reason is how people learn to trust autonomous routing, and how they correct it when it picks wrong.

4. Workstreams

Which parts are still open?

The incident broken into parts, each with an owner, progress and how it was resolved. A part closes on its own while the incident stays open. A resolved part gets a toe tag.

5. The record

How did it end, and what keeps it dead?

Written from the log when the incident closes. It covers the timestamps, how each part was resolved and the improvements, each with an owner. Each line links back to the moment in the timeline it came from.

Still open in the notes
  • CaptainMorgue is likely a hosted service. What happens to the incident if it goes down?
  • Demo faults: which ones, on which cluster, and how it resets between runs.
  • How ownership is known: service catalog, CODEOWNERS, on-call, or past incidents.
  • Whether direct A2A calls between agents are allowed, or every call must become an event.
  • Elasticsearch as the store of record or a search index, and keyword or semantic retrieval.
  • Per-person permissions on what CaptainMorgue reads for them.
  • Elected managers: must the person accept, and what happens to a one-person team at the top?
  • Agent0: copy findings into the log or link to them, and who watches the credits.
